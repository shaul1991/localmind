# goal — AGENTS.md 코어 전용화

## 무엇이 문제인가

localmind는 `great-reduction`(2026.07.9)으로 **코드**를 코어 전용으로 줄였고(-31k줄, MCP 도구
4종), 메타(SDD 스킬·페르소나)는 결국 별도 저장소 `localmind-addons`로 나갔다. 그런데
**작업 규약 문서는 함께 줄지 않았다.** 분리는 파일 단위로만 일어났고 권위 단위로는 갈리지
않았다.

2026-08-07 실측:

| 영역 | 줄 수 |
|---|---|
| localmind 코어(specs·package-lock 제외) | 17,072 |
| └ `scripts/` / `src/` / `docs/` / 루트 md | 6,518 / 5,736 / 1,971 / 1,201 |
| localmind-addons(specs 제외) | 1,342 · 애드온 4종 active |

`AGENTS.md` 460줄 중 **약 300줄이 애드온이 이미 소유한 방법론**이다. 구체적 증상 셋:

1. **정본 선언이 둘이다.** `AGENTS.md:150`은 자신을 "SDD 구현 완료 규칙의 **정본(SSoT)**"이라
   선언한다. 같은 워크플로에 대해 `localmind-addons/addons/goal-impl/skills/goal-impl/SKILL.md:40`은
   "sdd-5docs의 요구가 **그대로 정본**"이라 선언한다. 두 정본이 공존하면 갱신되지 않는 쪽이
   조용히 이긴다 — 이것은 문서 취향 문제가 아니라 **결함**이다.
2. **소멸한 것을 계속 가리킨다.** 아카이브된 `sdd-toolkit` 참조 7회, great-reduction으로
   소멸한 페르소나(designer·ux-reviewer·backend-dev·architect) 참조 4회.
3. **이 저장소에 적용되지 않는 규칙이 실려 있다.** "프로젝트 계약 저장소" 절 25줄은 L410–411에서
   스스로 *"localmind 자체는 예외 — 외부 바이브 코딩 프로젝트용"*이라고 밝힌다.

## 왜 지금인가

애드온 4종(`localmind-core`·`sdd-5docs`·`goal-impl`·`shape`)이 전부 active이고 이 기기에
설치돼 있다(2026-08-07 실측). **방법론을 받아줄 곳이 이미 존재한다** — 지금까지는 이관처가
없어서 남겨둘 이유가 있었지만 그 이유가 사라졌다.

동시에 `AGENTS.md`는 **현재 이 저장소를 실제로 규율하는 유일한 문서**다(`~/.localmind/rules/base`는
존재하나 `~/.claude/CLAUDE.md`가 import하지 않아 미배포). 규율자가 하나뿐이므로 그 하나가
낡은 것을 가리키는 비용이 그대로 작업 품질이 된다.
