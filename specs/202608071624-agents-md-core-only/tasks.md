# tasks — AGENTS.md 코어 전용화

작업 대상은 `AGENTS.md` 한 파일이라 **병렬 위임 불가**(같은 파일 충돌). T1 → T2 → T3 순차.

---

- [x] **T1** `specs/202608071624-agents-md-core-only/verify.sh` 신규 — AC 결정적 검증기

  **무엇을**: 새 파일 하나. `AGENTS.md`(저장소 루트)를 읽어 spec.md의 AC를 판정한다.
  다른 파일은 만들지도 고치지도 않는다.

  **계약**: `bash specs/202608071624-agents-md-core-only/verify.sh`로 실행. 저장소 루트에서
  실행하는 것을 전제하지 말고 **스크립트 위치 기준으로 저장소 루트를 찾는다**. 출력은 AC별
  한 줄 `PASS <id> <설명>` 또는 `FAIL <id> <설명>`, 마지막에 집계 한 줄. 종료코드는 전부
  통과 시 `0`, 하나라도 실패면 `1`.
  검사 3종류를 구현한다 — ① **금지 문자열**(등장 시 FAIL): AC1.1–1.3·2.1–2.3·3.1–3.3
  ② **필수 문자열**(부재 시 FAIL): AC1.4·4.1–4.7·5.1 ③ **줄 수 범위**: AC6.1(≤200)·AC6.2(≥100).
  판정 문자열은 spec.md의 FR4 표와 각 AC 문구를 그대로 쓴다.

  **근거**: plan "검증" 절 · spec FR1–FR6.
  **불변식**: 이 스크립트는 `AGENTS.md`를 **읽기만** 한다 — 절대 수정하지 않는다.

  **함정**: 절 제목 문자열(예: `## 변경 등급 티어`)로 부재를 판정할 때, 위임 절이 그 단어를
  설명으로 언급하면 오탐이 난다 — **`^## ` 헤더 매칭**으로 좁힌다. AC2.2의 페르소나 이름은
  일반 영단어(`architect` 등)와 겹치므로 백틱·괄호를 포함한 실제 등장 형태로 좁히고, 무엇을
  매칭했는지 FAIL 메시지에 출력한다. grep 종료코드 1(매칭 없음)이 `set -e`로 스크립트를
  죽이지 않게 처리한다.

  **됐는지 아는 법**: **현행(미편집) `AGENTS.md`에서 먼저 실행해 FAIL이 나오는 것을 눈으로
  확인한다** — 이 시점에 통과하면 검증기가 아무것도 잡지 못하는 것이므로 결함이다. 최소
  AC1.1·2.1·3.3·6.1이 FAIL이어야 한다. 그 관찰(출력)을 review.md에 남긴다.

  **막혔을 때**: AC 문구가 모호해 판정 문자열을 못 정하면 추측하지 말고 저작자에게 되묻는다.

- [x] **T2** `AGENTS.md` 편집 — 절 단위 수술 (T1 완료 후)

  **무엇을**: 저장소 루트 `AGENTS.md`만 수정. plan.md의 **절별 처리표**가 대상 좌표의 정본이다.

  **어떻게 생겼는가**:
  - **유지 절은 원문을 그대로 둔다** — 문장을 다시 쓰지 않는다(재작성이 이 작업 최대 위험).
    유지 대상: 최상위 전제 · 범위 우선순위 · PR 리뷰 대응 · 버전·릴리스(CalVer 전체) ·
    오픈소스 대상 + 구현 규율에서 살리는 4항목(git commit/push · 결정 로그 태그 ·
    Open questions 취소선 · 도그푸드 측정 위생).
  - **새로 쓰는 것은 위임 절 하나**: 제목은 `## 작업 방법론 — 애드온이 정본`. 세 가지에
    답한다 — ① 영역별 정본 애드온을 **이름으로** 지목(`sdd-5docs`=문서 체계·비례 원칙,
    `goal-impl`=구현 착수/재개/완료, `localmind-core`=brief·결정 3층·기록 소환)
    ② **애드온 미설치 시 비차단**으로 진행하고 그 사실을 보고한다 ③ 위임해도 **요구는
    약해지지 않는다**(TDD·자기검증·base 확인·정직 보고는 위임처에서 동등하게 유지).
  - 디자인 절은 제목을 유지하되 페르소나·`sdd-toolkit` 템플릿 참조를 걷어내고 **원칙만**
    남긴다(직관성 · 상태 가시성 · 디버깅/추적 용이성 · 충돌 시 가시성 우선).

  **근거**: plan.md 절별 처리표 · spec FR1–FR6.
  **불변식**: FR4 표의 7개 규칙은 **의미가 보존**된다 — 삭제도 완화도 아니다.

  **함정**: ① 남은 절이 삭제된 절을 가리키는 **댕글링 상호참조**(예: "위 규약 7", "아래
  변경 등급 티어 절", "규약 6과 동일")가 생긴다 — 삭제 후 전수 검색해 정리한다.
  ② `구현 규율` 절을 통째로 지우면 살려야 할 4항목이 함께 죽는다 — 분할이지 삭제가 아니다.
  ③ CalVer 절은 길지만 **localmind 고유**다 — 길이를 이유로 줄이지 않는다.

  **됐는지 아는 법**: `bash specs/202608071624-agents-md-core-only/verify.sh`가 종료코드 0으로
  전부 PASS. 추가로 **댕글링 참조 0**을 직접 확인한다(삭제된 절 제목·"규약 N" 형태 grep).

  **막혔을 때**: 어떤 절이 유지/삭제인지 처리표로 판단이 안 되면 되묻는다 — 임의 판단 금지.
